# Lecture 24: Memory Management Techniques | Contiguous Memory Allocation

## 1. Why many processes in memory

In a multi-programming environment, many processes sit in main memory (the Ready Queue). This keeps CPU utilization high and makes the computer responsive to users.

- **Why many processes in RAM:** If one process goes for I/O, or is context-switched out when its time quantum ends (time sharing), the CPU gets another process at once and never sits idle.

## 2. Sharing and managing main memory

To realize this performance gain, several processes must stay in memory. So we must **share** main memory. As a result, we must **manage** main memory for all the different processes.

- **The problem:** RAM is one big range of addresses, for example 0 to 1 GB. The start of RAM is reserved for the OS, because the OS is the first program loaded. The OS must decide where each process (P1, P2, P3, ...) sits. It must keep **isolation and memory protection** while doing so.

- **What goes wrong without protection:**
  - P1 is given locations 50 to 60 (60 inclusive). P2 is given 60 to 70. Some space is left free. P3 is given 90 to 100. The P1 and P2 boundaries touch.
  - A buggy or mischievous programmer of P1 writes `current address + 5`. With current address = 60, P1 now reads and writes location 65, which is P2's memory.
  - The same happens in real C++ programs when a garbage or huge value (like `INT_MAX`) gets added to an address. It can land in another process's memory.
  - **Result:** This breaks isolation. Each process should run independently. P1 does not know P2 is in memory, and neither can touch the other's memory area. It is also a security threat.

- **Fix:** The OS never lets a user process access RAM directly. It puts a layer in between: logical addresses plus address translation. This is described below.

## 3. Logical versus Physical Address Space

**Idea:** It is like shifting the origin of a coordinate system in maths. Every process gets its own address counting that starts from 0.

- **Example sizes:** P1 is 16 KB (stack, heap, data, code). Its addresses run 0 to 16 KB. P2 is also 16 KB, and its addresses also run 0 to 16 KB. A 5 KB program runs 0 to 5 KB.
- **Programmer's view:** The program is written as if it alone is in memory, starting at address 0. The OS gives this freedom for isolation.
- **Mapping:** The OS maps the logical 0 to some real location in RAM. P1's 0 is mapped to 128, so P1 occupies 128 to 144 physically. P2's 0 is mapped to 64, so P2 occupies 64 to 80 physically.
- **Address translation:** The user (user mode) never knows the 64 or the 128. The OS hides them. This is abstraction. The mapping is called **address translation**.

For each process, the OS stores two values:

- **Base:** Where the process's logical 0 actually sits in physical memory (P1: 128, P2: 64).
- **Offset (limit):** How far the process may go (P1: 16, P2: 16, in KB).

**Example of protection:** P2's programmer writes `0 + 129`, a random value added to an address. The program tries to access logical address 129.

- Physical address = base + 129 = 64 + 129 = 193.
- P2 is allowed only up to 64 + 16 = 80. Location 193 may belong to another process, say P4.
- Using base and offset, the OS sees that P2 is going out of bounds. It throws a trap (exception) for an illegal operation: trying to access an address that belongs to another process.

### a. Logical Address

| Point | Detail |
|-------|--------|
| i. | An address generated by the **CPU**. |
| ii. | The address of an instruction or data used by a process. |
| iii. | The user can access the logical address of the process. |
| iv. | The user has indirect access to the physical address through the logical address. |
| v. | A logical address does not exist physically. Hence it is also called a **Virtual address.** |
| vi. | The set of all logical addresses generated by any program is the Logical Address Space. |
| vii. | **Range: 0 to _max_.** |

- **iii. Example:** In a C++ program, printing `&a` of a variable shows a logical address, not the actual RAM address. The same holds for addresses of heap allocations.
- **iv. Indirect:** The stored base is added to the logical address to reach the physical address.
- **vi. Example:** 0 to 16 KB is P2's logical (virtual) address space.
- **vii. max:** How far the program is addressable, which is its size.

### b. Physical Address

| Point | Detail |
|-------|--------|
| i. | An address loaded into the memory-address register of the physical memory. |
| ii. | The user can never access the physical address of the program. |
| iii. | The physical address is in the memory unit. It is a location in main memory physically. |
| iv. | A physical address can be accessed by a user indirectly but not directly. |
| v. | The set of all physical addresses corresponding to the logical addresses is the Physical Address Space. |
| vi. | It is computed by the **Memory Management Unit (MMU).** |
| vii. | **Range: (R + 0) to (R + max), for a base value R.** |

- **iii. Example:** Both P1 and P2 see 0 to 16 KB. Physically they are stored at 128 to 144 and 64 to 80.
- **v. Example:** 64 to 80 is the physical address space of P2, corresponding to its logical 0 to 16 KB.
- **vi. MMU:** The unit that does the add and compare work.
- **vii. R:** The base value. It is the start address of the space allocated to the process in physical RAM.

### c. The MMU

**The runtime mapping from virtual to physical address is done by a hardware device called the memory-management unit (MMU).**

### d. User's view

The user's program generates the logical address, and the user thinks the program runs there. But the program needs physical memory to execute.

- Every address you see in your code (variables, heap memory) is logical. The process is allocated in RAM, but the user never needs to know where.

## 4. How the OS manages isolation and protection (Memory Mapping and Protection)

a. The OS provides the **Virtual Address Space (VAS)** concept.
   - Every process gets addresses from 0 to its max, each with its own separate count.

b. To separate memory space, we need to determine the range of legal addresses a process may access. We must also ensure the process can access only these legal addresses.
   - **Example:** The legal range of P2 is 64 to 80. It starts at 64 in physical memory and can go only up to +16.

c. The **relocation register** holds the smallest physical address (base address [R]). The **limit register** holds the range of logical addresses. For example, relocation = 100040 and limit = 74600.
   - Both registers are part of the MMU hardware. Base (64 for P2) goes in the relocation register. Offset (16 for P2) goes in the limit register.

d. Each logical address must be less than the limit register.
   - All of P2's instructions and data (code section, data segment) lie between logical 0 and 16 KB.

e. The MMU maps the logical address dynamically by adding the value in the relocation register.
   - At run time the MMU checks each logical address against the limit register, adds the relocation register, and gives access to that physical location, for reading and writing.

f. When the CPU scheduler selects a process, the dispatcher loads the relocation and limit registers with the correct values as part of the context switch. Every address generated by the CPU (logical address) is checked against these registers. So we protect both the OS and other users' programs and data from being modified by the running process.
   - **Per-process values:** Each process sits at a different place in RAM, so each has its own relocation and limit values. On every context switch the dispatcher loads the values of the process being restored. So the limit register value changes when another process comes in.

g. Any attempt by a program in user mode to access OS memory or other users' memory causes a trap in the OS. The OS treats the attempt as a fatal error.

h. **Address Translation**

   ```mermaid
   flowchart LR
       CPU[CPU] -- Logical address --> CMP{"<"}
       LR[Limit Register] --> CMP
       CMP -- Yes --> ADD(("+"))
       RR[Relocation Register] --> ADD
       ADD -- Physical Address --> MM[Main Memory]
       CMP -- No --> TRAP[trap: addressing error]
   ```

   - **MMU:** The whole box (limit check plus relocation add) is the MMU.
   - **Worked example:** A process of size 10 KB with base = 50 and limit = 10.
     - **Address 5:** The CPU generates logical address 5. Is 5 < 10? Yes. Physical = 5 + 50 = 55, the actual address in RAM.
     - **Address 15:** The CPU generates logical address 15. Is 15 < 10? No. This is an addressing error, and an exception is thrown. Beyond 10 there is no legal instruction for this process.

## 5. Allocation Method on Physical Memory

Logical memory is only an abstraction the OS gives. The real question is how the OS places P1, P2, ... in actual main memory.

| Method | Note |
|--------|------|
| a. Contiguous Allocation | Covered in this lecture. Not used nowadays. |
| b. Non-contiguous Allocation | Covered in the next lecture. Better, and used today. |

## 6. Contiguous Memory Allocation

**Example:** RAM 0 to 128 holds the OS, and 128 to 200 is free. A new process P1 (say 10 KB) arrives. The OS allocates, say, 200 to 300 to it. Every address of P1 is in one continuous run, with no gaps. P2 is likewise placed whole.

a. In this scheme, each process is contained in a single contiguous block of memory.

### b. Fixed Partitioning

i. Main memory is divided into partitions of equal or different sizes.
   - **When:** Partitions are made before any process is loaded.
   - **Sizes:** Equal, for example 4 MB, 4 MB, 4 MB, 4 MB. Or different, for example 4 MB, 6 MB, 10 MB, 4 MB (or 5, 2, 10).
   - **Rule:** A partition can hold at most one process. An arriving process takes a partition that has no process in it.

ii. Fixed Partitioning diagram (contiguous memory allocation):

   ```
                         +------------------+
                         | Operating System |  partition for OS
                         +------------------+
   3 MB [Process P1] --> | 3 MB             |  partition 1         Unused Space
                         | 1 MB  (unused)   |                      (External Fragmentation)
                         +------------------+                      +------+
   3 MB [Process P2] --> | 3 MB             |  partition 2         | 1 MB |
                         | 1 MB  (unused)   |                      | 1 MB |
                         +------------------+                      | 1 MB |
   3 MB [Process P3] --> | 3 MB             |  partition 3         | 1 MB |
                         | 1 MB  (unused)   |                      +------+
                         +------------------+
   3 MB [Process P4] --> | 3 MB             |  partition 4         [Process P5]  4 MB
                         | 1 MB  (unused)   |                      P5 can't be executed even though
                         +------------------+                      there is 4 MB space available but
                           ^ the unused 1 MB in each               not contiguous.
                             partition = Internal Fragmentation
   ```

   - **Setup:** OS at the start, four 4 MB partitions. P1 to P4 are 3 MB each, so each partition keeps 1 MB free.

iii. Limitations:

1. **Internal Fragmentation:** If the process is smaller than its partition, part of the partition is wasted and stays unused. This wastes memory and is called internal fragmentation.
   - **Example:** A 4 MB partition holds a 3 MB process. The leftover 1 MB inside the partition is internal fragmentation, meaning fragmentation within a partition.

2. **External Fragmentation:** The total unused space of various partitions cannot be used to load processes. Space is available, but not in contiguous form.
   - **Fragments:** Small pieces. Memory has broken into them.
   - **Combined effect:** With both kinds, memory is not used in an optimized way.
   - **Example:** 1 MB is free in each of 4 partitions, so 4 MB is free in total. P5 (4 MB) still cannot be allocated. The four 1 MB pieces are at far-apart addresses, and contiguous allocation needs one continuous block.

3. **Limitation on process size:** If a process is larger than the largest partition, it cannot be loaded. So a process cannot be larger than the largest partition.
   - **Example (equal):** All partitions are 4 MB and P6 is 5 MB. It cannot be loaded. Two partitions cannot be combined to hold one process, because there is no such management here.
   - **Example (unequal):** If the largest partition is 10 MB, an 11 MB process cannot be loaded.

4. **Low degree of multi-programming:** In fixed partitioning, the degree of multiprogramming is fixed and very low. The partition size cannot vary with the size of the processes.
   - **Degree of multiprogramming:** The number of processes that can be in RAM at one time.
   - **Limit:** The number of processes in RAM is at most the number of partitions, since a partition holds at most one process. Example: four 4 MB partitions holding four 1 MB processes leave 3 MB empty in each. Still only 4 processes fit.

### c. Dynamic Partitioning

i. The partition size is not declared initially. It is declared at the time of process loading.
   - **Benefit:** It solves the problems of fixed partitioning. A partition is made of exactly the size the arriving process needs. Nothing is fixed beforehand.
   - **Example:** OS at the start. P1 (5 MB) arrives, so a partition from 5 to 10 MB is made for it. P2 (2 MB) gets a partition up to 12 MB. P3 (3 MB) gets one up to 15 MB. P4 (4 MB) gets one up to 19 MB.

ii. Dynamic Partitioning diagram (Process Size = Partition Size):

   ```
                            +------------------+
                            | Operating System |  partition for OS
                            +------------------+
   5 MB [Process P1] -----> | Process P1 (5 MB)|  partition 1
                            +------------------+
   2 MB [Process P2] -----> | Process P2 (2 MB)|  partition 2
                            +------------------+
   3 MB [Process P3] -----> | Process P3 (3 MB)|  partition 3
                            +------------------+
   4 MB [Process P4] -----> | Process P4 (4 MB)|  partition 4
                            +------------------+
   ```

iii. Advantages over fixed partitioning:

1. **No internal fragmentation:** A 3 MB process gets a 3 MB partition, not a 4 MB one. Nothing is left over inside a partition.

2. **No limit on process size:** An 11 MB process just gets an 11 MB partition.

3. **Better degree of multi-programming:** In fixed partitioning, processes were capped at the number of partitions. The internal fragmentation space could not take another process. Here more processes fit in memory at once.

iv. Limitation:

1. **External fragmentation**

   ```
                            +------------------+
                            | Operating System |  partition for OS
                            +------------------+
                            |    5 MB Free     |  partition 1      [Process P1]  Completed
                            +------------------+
   2 MB [Process P2] -----> | Process P2 (2 MB)|  partition 2
                            +------------------+
                            |    3 MB Free     |  partition 3      [Process P3]  Completed
                            +------------------+
   4 MB [Process P4] -----> | Process P4 (4 MB)|  partition 4
                            +------------------+
                                                                   [Process P5 (8 MB)]  X
                                                                   P5 can't be loaded into memory
                                                                   even though there is 8 MB space
                                                                   available but not contiguous.

                 External Fragmentation in Dynamic Partitioning
   ```

   - **After time t:** P1 (5 MB partition) and P3 (3 MB partition) complete and exit. P2 and P4 stay. Free space is 5 MB + 3 MB = 8 MB.
   - **Failure:** P5 (8 MB) arrives. 8 MB is free in total, but it is not contiguous, so P5 cannot be allocated.
