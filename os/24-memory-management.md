# Lecture 24: Memory Management Techniques | Contiguous Memory Allocation

1. In Multi-programming environment, we have multiple processes in the main memory (Ready Queue) to keep the CPU utilization high and to make computer responsive to the users.
   - Why many processes in RAM: if one process goes for I/O, or is context-switched out when its time quantum ends (time sharing), the CPU should get another process at once and never sit idle.
2. To realize this increase in performance, however, we must keep several processes in the memory; that is, we must **share** the main memory. As a result, we must **manage** main memory for all the different processes.
   - The problem: RAM is one big range of addresses (e.g., 0 to 1 GB). The start of RAM is reserved for the OS (the OS is the first program loaded). The OS must decide where each process (P1, P2, P3, ...) sits, while keeping **isolation and memory protection**.
   - Example of what goes wrong without protection: P1 is given locations 50 to 60 (60 inclusive), P2 is given 60 to 70, some space is left free, P3 is given 90 to 100. The P1 and P2 boundaries touch.
     - A buggy (or mischievous) programmer of P1 writes `current address + 5`. With current address = 60, P1 now reads/writes location 65, which is P2's memory.
     - Same thing happens in real C++ programs when some garbage/huge value (like `INT_MAX`) gets added to an address: the address goes out of bounds and can land in another process's memory.
     - This breaks isolation (each process should run independently: P1 does not know P2 is in memory and vice versa, and neither can interfere with the other's memory area). It is a security threat.
   - Fix: the OS never lets a user process access RAM directly. It puts a layer in between (logical addresses + address translation), described below.
3. **Logical versus Physical Address Space**
   - Idea (like shifting the origin of a coordinate system in maths): every process gets its own address counting starting from 0.
     - P1 is 16 KB (stack, heap, data, code). Its addresses run 0 to 16 KB. P2 is also 16 KB; its addresses also run 0 to 16 KB. A 5 KB program runs 0 to 5 KB.
     - The programmer writes the program as if it alone is in memory starting at address 0. The OS gives this freedom for isolation.
     - The OS maps the logical 0 to some real location in RAM. E.g., P1's 0 is mapped to 128, so P1 occupies 128 to 144 physically. P2's 0 is mapped to 64, so P2 occupies 64 to 80 physically.
     - The user (user mode) never knows the 64 or the 128. The OS hides it (abstraction). This mapping is called **address translation**.
   - For each process the OS stores two values:
     - **Base**: where the process's logical 0 actually sits in physical memory (P1: 128, P2: 64).
     - **Offset (limit)**: how far the process may go (P1: 16, P2: 16, in KB).
   - Example of protection: P2's programmer writes `0 + 129` (a random value added to an address) and tries to access logical address 129.
     - Physical address = base + 129 = 64 + 129 = 193.
     - P2 is allowed only up to 64 + 16 = 80. Location 193 may belong to another process (say P4).
     - Using base and offset, the OS sees P2 is going out of bounds and throws a trap (exception): illegal operation, trying to access an address that belongs to some other process.

   - a. Logical Address
      - i. An address generated by the **CPU**.
      - ii. The logical address is basically the address of an instruction or data used by a process.
      - iii. User can access logical address of the process.
         - E.g., in a C++ program, printing `&a` of a variable shows a logical address, not the actual RAM address. Same for addresses of heap allocations.
      - iv. User has indirect access to the physical address through logical address.
         - Indirect: the stored base is added to the logical address to reach the physical address.
      - v. Logical address does not exist physically. Hence, aka, **Virtual address.**
      - vi. The set of all logical addresses that are generated by any program is referred to as Logical Address Space.
         - E.g., 0 to 16 KB is P2's logical (virtual) address space.
      - vii. **Range: 0 to _max_.**
         - max = how far the program is addressable (its size).

   - b. Physical Address
      - i. An address loaded into the memory-address register of the physical memory.
      - ii. User can never access the physical address of the Program.
      - iii. The physical address is in the memory unit. It's a location in the main memory physically.
         - Both P1 and P2 see 0 to 16 KB, but physically they are stored at 128 to 144 and 64 to 80.
      - iv. A physical address can be accessed by a user indirectly but not directly.
      - v. The set of all physical addresses corresponding to the Logical addresses is commonly known as Physical Address Space.
         - E.g., 64 to 80 is the physical address space of P2 (corresponding to its logical 0 to 16 KB).
      - vi. It is computed by the **Memory Management Unit (MMU).**
         - MMU = the unit that does the add/compare work.
      - vii. **Range: (R + 0) to (R + max), for a base value R.**
         - R = base value = start address of the space allocated to the process in physical RAM.

   - c. **The runtime mapping from virtual to physical address is done by a hardware device called the memory-management unit (MMU).**

   - d. The user's program mainly generates the logical address, and the user thinks that the program is running in this logical address, but the program mainly needs physical memory in order to complete its execution.
      - Every address you see in your code (variables, heap memory) is logical. The process is actually allocated in RAM, but the user never needs to know where. The OS hides the underlying complexity.

   - e. Relocation register diagram:

      ```
                          +---------------------+
                          |     Relocation      |
                          |      Register       |
                          |      [ 14000 ]      |
                          |          |          |
      +-----+  Logical    |          v          |  Physical
      | CPU | ----------> |         (+)         | -----------> Memory
      +-----+  Address    |                     |  Address
                 356      +---------------------+   14356
      ```

4. How OS manages the isolation and protect? **(Memory Mapping and Protection)**
   - a. OS provides this Virtual Address Space (VAS) concept.
      - Every process gets addresses from 0 to its max, each with its own separate count.
   - b. To separate memory space, we need the ability to determine the range of legal addresses that the process may access and to ensure that the process can access only these legal addresses.
      - E.g., legal range of P2 is 64 to 80: starts at 64 in physical memory and can go only up to +16.
   - c. The relocation register contains value of smallest physical address (Base address [R]); the limit register contains the range of logical addresses (e.g., relocation = 100040 & limit = 74600).
      - Both registers are part of the MMU hardware. Base (64 for P2) goes in the relocation register; offset (16 for P2) goes in the limit register.
   - d. Each logical address must be less than the limit register.
      - All of P2's instructions and data (code section, data segment) lie between logical 0 and 16 KB, so any legal logical address is below the limit.
   - e. MMU maps the logical address dynamically by adding the value in the relocation register.
      - While a program runs, the CPU keeps generating logical addresses; at run time the MMU checks each against the limit register, adds the relocation register, and gives access to that physical location (both for reading and for writing).
   - f. When CPU scheduler selects a process for execution, the dispatcher loads the relocation and limit registers with the correct values as part of the context switch. Since every address generated by the CPU (Logical address) is checked against these registers, we can protect both OS and other users' programs and data from being modified by running process.
      - Each process sits at a different place in RAM, so each has its own relocation and limit values. On every context switch the dispatcher loads the values of the process being restored. So yes, the limit register value changes when another process comes in.
   - g. Any attempt by a program executing in user mode to access the OS memory or other users' memory results in a trap in the OS, which treat the attempt as a fatal error.
   - h. **Address Translation**

      ```mermaid
      flowchart LR
          CPU[CPU] -- Logical address --> CMP{"<"}
          LR[Limit Register] --> CMP
          CMP -- Yes --> ADD(("+"))
          RR[Relocation Register] --> ADD
          ADD -- Physical Address --> MM[Main Memory]
          CMP -- No --> TRAP[trap: addressing error]
      ```

      - The whole box (limit check + relocation add) is the MMU.
      - Worked example: process of size 10 KB, base = 50, limit = 10.
        - CPU generates logical address 5. Is 5 < 10? Yes. Physical = 5 + 50 = 55, the actual address in RAM.
        - CPU generates logical address 15. Is 15 < 10? No. Addressing error: an exception is thrown (beyond 10 there is no legal instruction for this process).

5. **Allocation Method on Physical Memory**
   - Logical memory is only an abstraction the OS gives; the real question is how the OS places P1, P2, ... in actual main memory.
   - a. Contiguous Allocation
   - b. Non-contiguous Allocation
   - This lecture covers contiguous; non-contiguous is the next lecture. Non-contiguous techniques are better and are the ones used today; contiguous allocation is not used nowadays.

6. **Contiguous Memory Allocation**
   - Example: RAM 0 to 128 holds the OS, 128 to 200 is free, ... A new process P1 (say 10 KB) arrives. The OS finds free space and allocates, say, 200 to 300 to it. Every address of P1 (0, 1, 2, 3, ...) is put in one continuous run; the process is not split into parts with gaps in between. P2 is likewise placed whole.

   - a. In this scheme, each process is contained in a single contiguous block of memory.
   - b. **Fixed Partitioning**
      - i. The main memory is divided into partitions of equal or different sizes.
         - Partitions are made before any process is loaded.
         - Equal sizes: e.g., 4 MB, 4 MB, 4 MB, 4 MB. Different sizes: e.g., 4 MB, 6 MB, 10 MB, 4 MB.
         - Rule: a partition can hold at most one process. An arriving process takes a partition that has no process in it.
      - ii. Fixed Partitioning diagram (contiguous memory allocation):

         ```
                               +------------------+
                               | Operating System |  partition for OS
                               +------------------+
         3 MB [Process P1] --> | 3 MB             |  partition 1         Unused Space
                               | 1 MB  (unused)   |                      (External Fragmentation)
                               +------------------+                      +------+
         3 MB [Process P2] --> | 3 MB             |  partition 2         | 1 MB |
                               | 1 MB  (unused)   |                      | 1 MB |
                               +------------------+                      | 1 MB |
         3 MB [Process P3] --> | 3 MB             |  partition 3         | 1 MB |
                               | 1 MB  (unused)   |                      +------+
                               +------------------+
         3 MB [Process P4] --> | 3 MB             |  partition 4         [Process P5]  4 MB
                               | 1 MB  (unused)   |                      P5 can't be executed even though
                               +------------------+                      there is 4 MB space available but
                                 ^ the unused 1 MB in each               not contiguous.
                                   partition = Internal Fragmentation
         ```

         - OS at the start; four 4 MB partitions; P1 to P4 are 3 MB each, so each partition keeps 1 MB free.
      - iii. Limitations:
         1. **Internal Fragmentation:** if the size of the process is lesser then the total size of the partition then some size of the partition gets wasted and remain unused. This is wastage of the memory and called internal fragmentation.
            - E.g., the 4 MB partition holds a 3 MB process: the leftover 1 MB inside the partition is internal fragmentation (fragmentation within a partition).
         2. **External Fragmentation:** The total unused space of various partitions cannot be used to load the processes even though there is space available but not in the contiguous form.
            - Fragments = small pieces. Memory has broken into small pieces.
            - E.g., 1 MB free in each of 4 partitions = 4 MB free in total, but P5 (4 MB) still cannot be allocated: the four 1 MB pieces are at far-apart addresses, and contiguous allocation needs one continuous block.
            - Both kinds together mean space stays unused; memory is not utilized in an optimized way.
         3. Limitation on process size: If the process size is larger than the size of maximum sized partition then that process cannot be loaded into the memory. Therefore, a limitation can be imposed on the process size that is it cannot be larger than the size of the largest partition.
            - E.g., all partitions 4 MB, P6 is 5 MB: it cannot be loaded. Two partitions cannot be combined to hold one process; there is no such management here.
            - With unequal partitions the same holds: if the largest is 10 MB, an 11 MB process cannot be loaded.
         4. Low degree of multi-programming: In fixed partitioning, the degree of multiprogramming is fixed and very less because the size of the partition cannot be varied according to the size of processes.
            - Degree of multiprogramming = number of processes that can be in RAM at one time.
            - Number of processes in RAM can be at most the number of partitions, since a partition holds at most one process. E.g., four 4 MB partitions holding four 1 MB processes leave 3 MB empty in each, yet still only 4 processes fit.

   - c. **Dynamic Partitioning**
      - i. In this technique, the partition size is not declared initially. It is declared at the time of process loading.
         - It solves the problems of fixed partitioning: a partition is made of exactly the size the arriving process needs.
         - E.g., OS at the start. P1 (5 MB) arrives: partition from 5 to 10 MB is made for it. P2 (2 MB): partition up to 12 MB. P3 (3 MB): up to 15 MB. P4 (4 MB): up to 19 MB. Nothing is fixed beforehand; partitions are made as per need.
      - ii. Dynamic Partitioning diagram (Process Size = Partition Size):

         ```
                                  +------------------+
                                  | Operating System |  partition for OS
                                  +------------------+
         5 MB [Process P1] -----> | Process P1 (5 MB)|  partition 1
                                  +------------------+
         2 MB [Process P2] -----> | Process P2 (2 MB)|  partition 2
                                  +------------------+
         3 MB [Process P3] -----> | Process P3 (3 MB)|  partition 3
                                  +------------------+
         4 MB [Process P4] -----> | Process P4 (4 MB)|  partition 4
                                  +------------------+
         ```

      - iii. Advantages over fixed partitioning
         1. No internal fragmentation
            - A 3 MB process gets a 3 MB partition, not a 4 MB one, so nothing is left over inside a partition.
         2. No limit on size of process
            - An 11 MB process just gets an 11 MB partition.
         3. Better degree of multi-programming
            - In fixed partitioning, processes were capped at the number of partitions (internal fragmentation space could not take another process). Here more processes fit in memory at once.
      - iv. Limitation
         1. External fragmentation

            ```
                                     +------------------+
                                     | Operating System |  partition for OS
                                     +------------------+
                                     |    5 MB Free     |  partition 1      [Process P1]  Completed
                                     +------------------+
            2 MB [Process P2] -----> | Process P2 (2 MB)|  partition 2
                                     +------------------+
                                     |    3 MB Free     |  partition 3      [Process P3]  Completed
                                     +------------------+
            4 MB [Process P4] -----> | Process P4 (4 MB)|  partition 4
                                     +------------------+
                                                                            [Process P5 (8 MB)]  X
                                                                            P5 can't be loaded into memory
                                                                            even though there is 8 MB space
                                                                            available but not contiguous.

                          External Fragmentation in Dynamic Partitioning
            ```

            - After some time t, P1 (5 MB partition) and P3 (3 MB partition) complete and exit; P2 and P4 stay. Free: 5 MB + 3 MB = 8 MB.
            - P5 (8 MB) arrives. 8 MB is free in total, but not contiguous, so P5 cannot be allocated.

   - Fixed vs dynamic in short:
     - Fixed: RAM is divided into partitions beforehand (all the same size or different sizes like 5, 2, 10). One partition holds only one process, so a process that does not fill its partition causes internal fragmentation.
     - Dynamic: no fixed partitions; a partition as big as the process needs is made, which removes internal fragmentation. External fragmentation remains in both.
