# Lecture 7: 32-Bit vs 64-Bit OS

Common interview question: what do "32" and "64" mean, and why is 64-bit better?

## What the 32/64 refers to

- **CPU chip:** It sits on the motherboard. It holds billions of transistors, which are digital circuits built from gates like NAND and OR.
- **Registers:** The CPU builds registers from these circuits. A register is a place inside the CPU where the actual computation happens.
  - **Contents:** A register holds data and addresses. For `1 + 2` in code, `1` and `2` are loaded into registers and then added.
  - **Picture:** A register is a small memory block, or an array of bits.
- **32-bit register:** A 4-byte register is 4 × 8 = 32 bits. It holds 4 bytes of data, instruction or information at a time. A 32-bit processor has 32-bit registers.
- **64-bit register:** A 64-bit register is 8 bytes. It holds double the data at a time.

```
32-bit register (4 bytes):
| byte 1 | byte 2 | byte 3 | byte 4 |
 bit 0 .......................... bit 31

64-bit register (8 bytes):
| byte 1 | byte 2 | byte 3 | byte 4 | byte 5 | byte 6 | byte 7 | byte 8 |
 bit 0 ................................................... bit 63
```

- **Architecture:** CPU 1 with 32-bit registers and CPU 2 with 64-bit registers are two different architectures.
- **Hardware first:** Compatible software is built afterwards to run it. The OS on a 32-bit CPU is a 32-bit OS. The OS on a 64-bit CPU is a 64-bit OS.

1. A 32-bit OS has 32-bit registers. It can access 2^32 unique memory addresses. That is 4GB of physical memory.
   - **CPU's job:** The CPU goes to memory (RAM) addresses and fetches data. RAM is a series of locations with addresses 0, 1, 2, ..., n.
   - **Address count:** Each of the 32 bits can be 0 or 1 (2 values). So 32 bits give 2^32 unique addresses.
   - **Limit:** 2^32 bytes = 4GB, so a 32-bit CPU supports at most 4GB RAM. Even phones now have 8GB to 16GB RAM, so this is a big limitation.
   - **Addresses in hex (4 bytes):**

     ```
     first address : 00 00 00 00   (0)
     next address  : 00 00 00 01   (1)
     ...
     last address  : FF FF FF FF   (2^32 - 1)
     ```

2. A 64-bit OS has 64-bit registers. It can access 2^64 unique memory addresses. That is 17,179,869,184 GB of physical memory.
   - **Fix:** The register size was doubled to 64 bits to remove the 4GB limit.
   - **Range:** Addresses run from `00 00 00 00 00 00 00 00` (0) to `FF FF FF FF FF FF FF FF` (2^64 - 1). Each address is 8 bytes.
   - **Once and for all:** Building that much RAM is not practical, so doubling the register size was a permanent fix.
   - **History:** Until the early '90s, systems were 32-bit and 4GB RAM was enough. As demand grew, hardware improved until it could support much larger RAM. The whole move started from RAM.
3. A 32-bit CPU architecture can process 32 bits of data and information.
   - **Easy case:** Adding two 32-bit numbers is easy.
   - **Hard case:** Take two numbers that need 64 bits, such as `int a + b`. The CPU loads and adds one 32-bit half first. It writes the result somewhere in memory. Then it works on the other 32-bit half and writes that. This takes 2 cycles.
4. A 64-bit CPU architecture can process 64 bits of data and information.
   - **Same addition:** The CPU loads the whole 0-64 bit operand into its 64-bit register. It does the operation (add, subtract, and so on) in 1 cycle.
   - **Cycles matter:** Fewer cycles means better performance.
5. Advantages of 64-bit over the 32-bit operating system:

   a. **Addressable memory:** A 32-bit CPU has 2^32 memory addresses. A 64-bit CPU has 2^64 memory addresses.

   b. **Resource usage:** Installing more RAM on a system with a 32-bit OS does not change performance. Upgrade that system to the 64-bit version of Windows, and you will notice a difference.
      - **Extension of point a:** A 32-bit system cannot use more than 4GB of memory, so the extra RAM stick goes unused.
      - **On 64-bit:** Adding another 4GB RAM gets used.

   c. **Performance:** All calculations take place in the registers. When you do math in your code, operands are loaded from memory into registers. Larger registers let you perform larger calculations at the same time.
      - **Per cycle:** A 32-bit processor executes 4 bytes of data in 1 instruction cycle. A 64-bit processor executes 8 bytes in 1 instruction cycle.
      - **Cycle rate:** In 1 second there can be thousands to billions of instruction cycles, depending on the processor design.
      - **Always calculating:** The CPU calculates all the time. 64-bit data is done in one go instead of in 32-bit chunks.
      - **GHz:** The GHz rating (1 GHz, 4 GHz) is how many cycles the CPU does per second. A difference of one cycle multiplies into a big difference per second.

   d. **Compatibility:** A 64-bit CPU can run both 32-bit and 64-bit OS. A 32-bit CPU can only run a 32-bit OS.
      - **Backward compatibility:** A 32-bit OS on a 64-bit CPU uses only 32 bits of the register. The rest stay 0.

   e. **Better graphics performance:** 8-byte graphics calculations make graphics-intensive apps run faster.
      - **Why:** Graphics (for example games) add and subtract very large integers. On 64-bit, 8-byte calculations finish in one cycle, double the amount of 32-bit. So graphics-intensive apps run faster and more efficiently.

> **Interview:** Saying 3-4 of these points is enough. Two points you must remember are addressable memory (how much each can address) and how performance is better.
