# Lecture 26: Paging | Non-Contiguous Memory Allocation

## 1. Problem with dynamic partitioning

The main **disadvantage of dynamic partitioning is external fragmentation.**

1. It can be removed by compaction, but with overhead.
   - Compaction (defragmentation) must be done again and again as processes come and go, so the overhead keeps adding up.

2. **We need a more dynamic, flexible and optimal mechanism to load processes into the partitions.**

- **Recap example:** RAM holds the OS (4KB), P1 (2KB), P3 (1KB) and P2 (2KB). P1 and P2 exit, so the free list has two separate 2KB holes (2KB -> 2KB -> NULL). A new process P4 of 3KB arrives. 4KB is free in total, but no single hole is 3KB, so contiguous allocation fails.

## 2. Idea behind Paging

1. Say only two small non-contiguous free holes exist in memory, 1KB each.
2. The OS wants to allocate RAM to a process of 2KB. Contiguous allocation cannot do it, because it needs 2KB of contiguous space (external fragmentation).
3. **What if we divide the process into 1KB blocks?**
   - Part of the process goes into one hole and the rest into the other. This is non-contiguous allocation, and paging is such a method.

## 3. Paging

1. **Paging is a memory-management scheme that permits the physical address space of a process to be non-contiguous.**

2. It avoids external fragmentation and the need for compaction.

3. Divide physical memory into fixed-size blocks called **frames**. Divide logical memory into blocks of the same size called **pages**. Page size = frame size.
   - **Page:** A fixed-size piece of a process's logical (virtual, imaginary) address space: page 0, page 1, page 2, and so on. The process is its logical address space.
   - **Frame:** A fixed-size piece of real RAM (physical memory).
   - **Example:** A 64KB process with 16KB pages has 4 pages (page 0 to page 3). A 128KB RAM with 16KB frames has 8 frames. Assume the first frame holds the OS.
   - **Contiguous case:** Some frames hold other processes and the free frames are scattered. The 64KB process cannot be loaded because no 64KB contiguous hole exists. We would have to defragment first.
   - **Paging case:** Each page goes into any free frame, even if the frames are far apart (page 3 in one free frame, page 2 in another, and so on). RAM needs only enough free frames, not contiguous free space.
   - **One page, one frame:** A page needs exactly one frame because page size = frame size. A 16KB page needs a 16KB slot.
   - **Frame count:** RAM is bigger than a process, so it has more frames than the process has pages. Every frame is still the size of a page.

4. **Page size** is usually determined by the processor architecture. Traditionally, pages had a uniform size, such as 4,096 bytes. However, processor designs often allow two or more page sizes, sometimes simultaneously, due to the benefits.
   - Page size is a computer architecture topic, not covered here. For now assume it is fixed. Traditional systems used 4KB.
   - **Paging in short:** Divide the logical address space into pages and the physical address space into frames of the same size. Place pages in any free frames.

5. **Page Table**

   1. A data structure stores which page is mapped to which frame.
   2. **The page table contains the base address of each page in physical memory.**

   - **Contiguous vs paging:** In contiguous allocation, the MMU added the logical address (offset) to the base in the relocation register and checked it against the limit register. In paging, the MMU uses the page table to convert logical addresses to physical addresses.
   - **Example:** A 4-page process has page 0 -> frame 3, page 1 -> frame 7, page 2 -> frame 5, page 3 -> frame 2.
   - **Each process has its own page table.** Each process has its own logical address space, and its pages map to different frames. Another process P1 with 3 pages in other frames has a different table.
   - **Real layout:** The page table has no "page number" column. It is a simple array indexed from 0 to n that holds frame numbers. The page number is the index, like `a[0]`, `a[1]`.

6. Every address generated by the CPU (logical address) has two parts: a page number (p) and a page offset (d). The page number p is the index into the page table. It gives the base address of the corresponding frame in physical memory.

   **Worked example (address translation with bits):**

   - **Logical space:** Process P0 has 64 bytes. Page size = frame size = 16 bytes, so 4 pages. The logical address needs 6 bits (2^6 = 64). The left 2 bits are the page number p (2^2 = 4 pages). The right 4 bits are the offset d (2^4 = 16 bytes per page).
   - **Physical space:** Memory is 128 bytes, which is 8 frames of 16 bytes. The physical address needs 7 bits: 3 bits for the frame number f (2^3 = 8 frames) plus the same 4 offset bits d.
   - **Page table:** page 0 -> frame 3, page 1 -> frame 7, page 2 -> frame 5, page 3 -> frame 2.
   - **Logical address 25:** It is `01 1001`. p = `01` is page 1 (page 1 starts at 16). d = `1001` is 9. Check: base 16 + offset 9 = 25.
   - **Lookup:** The page table entry for page 1 gives frame 7 = `111`. Frame 7 starts at 7 × 16 = 112.
   - **Physical address:** `111 1001` = 112 + 9 = 121.
   - **Offset unchanged:** The whole page moves as it is into the frame. The page's base 16 maps to the frame's base 112, so any offset lands at the same offset in the frame. Only p is replaced by f, using the page table.

   | Logical address 25 | p = `01` (page 1) | d = `1001` (9) |
   |---|---|---|
   | **Physical address 121** | **f = `111` (frame 7)** | **d = `1001` (9)** |

   **Paging model of logical and physical memory**

   | Logical Memory Process P1 | Page Table (page -> frame) | Physical Memory (frame: content) |
   |---|---|---|
   | Page 0 | 0 -> 1 | 0: |
   | Page 1 | 1 -> 4 | 1: Page 0 |
   | Page 2 | 2 -> 3 | 2: |
   | Page 3 | 3 -> 7 | 3: Page 2 |
   | | | 4: Page 1 |
   | | | 5: |
   | | | 6: |
   | | | 7: Page 3 |

   - Process 1 has 4 pages (index 0 to 3). Page 0 goes to frame 1, page 1 to frame 4, page 2 to frame 3, page 3 to frame 7.

7. The page table is stored in main memory at process creation. Its base address is stored in the process control block (**PCB**).
   - Every process has its own PCB (register values, program counter, and so on), kept by the OS in the kernel area of RAM. It stores the base address of that process's page table.

8. A page table base register (**PTBR**) points to the current page table. Changing page tables needs only this one register, at context switch.
   - **Current page table:** The table of the process scheduled (running) now.
   - **Example:** P1 is running, so PTBR holds the address of P1's page table. P1 goes for I/O and P2 gets the CPU. On this context switch, the OS reads the page table address from P2's PCB and loads it into PTBR, replacing P1's value.
   - **Cost:** The only extra work paging adds to a context switch is changing this one register.

## 4. How paging avoids external fragmentation

1. Pages of a process can go into random free frames of physical memory.
   - In the example, frames 1, 4 and 6 were busy. The 64KB process was still loaded, with its pages in whichever frames were free. So paging has no external fragmentation.

## 5. Why paging is slow and how to make it fast

1. There are too many memory references to reach the desired physical location.
   - **Page table in RAM:** The page table is stored in RAM (the OS area). To reach physical location 121 for logical address 25, reference 1 goes to the page table in RAM to get the frame number. Reference 2 goes to the actual location in RAM. That is one extra memory reference per access, only because of the table.
   - **Context switches:** Processes context switch all the time, and each new process's page table also comes from RAM.
   - **Fix:** Paging is costly, so making it fast is necessary. The idea is caching.

## 6. Translation Look-aside Buffer (TLB)

1. Hardware support to speed up paging.
   - It is hardware, not software. The TLB is a piece of hardware holding a table. It is not stored in memory like the page table.

2. It is a hardware cache, a high-speed memory.
   - TLB access time is less than RAM access time. TLB hardware also costs more than RAM.

3. The TLB holds key-value pairs.
   - Key = page number. Value = frame number.

4. The page table is stored in main memory, so translation on every memory reference is slow.

5. After getting the frame for a page number from the page table, we put an entry into the TLB. Next time we get the value from the TLB directly, without the page table. This makes paging faster.
   - **Without TLB:** The CPU generates logical address (p, d). p indexes the page table in memory to get f. (f, d) is the physical address.
   - **With TLB:** The CPU first checks the TLB for p.
     - **First access:** Page `01` (for example address `01 1001`) is not in the TLB (miss). It is resolved through the page table, frame `111` is used, and the entry (`01` -> `111`) is also put into the TLB.
     - **Next access:** Any address starting with `01` (for example `01 0111`) does not go to the page table. The CPU finds `01` -> `111` in the TLB (hit), puts the 3 frame bits in front of d, and gets the physical address.
   - **Cache terms:** Entry found in the cache is a **hit**. Entry not found is a **miss**.
   - **Name:** This setup is called "paging hardware with TLB". Modern PCs normally have a TLB.

   **Paging hardware with TLB**

      ```
                logical
       CPU ---- address ---> [ p | d ]                        physical
                              |   |                           address
                              |   +---------------------> [ f | d ] ---> physical memory
                              |                              ^
                              +--> TLB                       |
                              |    page number | frame number|
                              |    ------------+------------ |
                              |         p      |     f  -----+ TLB hit
                              |                              |
                              +--> (TLB miss) page table     |
                                   index p ---> f -----------+
      ```

6. **TLB hit:** The TLB contains the mapping for the requested logical address.

7. **Address space identifier (ASID)** is stored in each TLB entry. An ASID uniquely identifies each process. It is used to **provide address space protection and allow the TLB to contain entries for several different processes.** When the TLB resolves virtual page numbers, it checks that the ASID of the running process matches the ASID of the entry. If it does not match, the attempt is treated as a TLB miss.
   - **Problem:** Each process has its own page table. On a context switch the page table (PTBR) changes, but the TLB still holds the previous process's entries.
     - **Example:** The TLB holds P0's entry page 10 -> frame 100. Context switch to P1. P1 also looks up page 10 and checks the TLB first, since it is fast. It finds page 10 -> frame 100, but that entry belongs to P0. P1 would access P0's memory location. This is wrong.
   - **Solution 1:** **Flush the TLB on every context switch.** This deletes all its entries.
     - **Not feasible:** Context switches are very fast and very frequent. Flushing every time means the TLB never fills with enough entries, so the cache is wasted. Resetting a hardware device also has its own cost each time.
   - **Solution 2:** **ASID** in each TLB entry. The TLB columns are ASID (process), page number, frame number.
     - P0 runs and stores (P0, page 10, frame 100). P1 comes after the context switch and looks up page 10. The entry for page 10 exists, but its ASID is P0, not P1, so it is a TLB miss for P1.
     - P1 goes to its own page table, resolves the frame (say 45), and adds (P1, page 10, frame 45) to the TLB.
     - **Benefit:** Address space protection, and the TLB holds entries of several processes at once with no flushing.

> **Interview:** Paging is a very important interview topic.
> - Is the page table separate for each process? Yes. Each process's logical address space maps to different frames in physical memory.
> - Where is the page table stored? In main memory.
> - How is paging made fast? Using the TLB, hardware support faster than memory.
> - Can the TLB have entries of different processes? Yes, handled using ASIDs.
> - Be ready to explain the bit-level translation (p, d to f, d using the page table) and the paging hardware with TLB diagram.
